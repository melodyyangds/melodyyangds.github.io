The story

Problem
Every audit asked the same things: who has access, does each person still need it, and who approved it. Answering took about two weeks of digging through email.
What I did
I added eligibility questions to the request form, so incomplete requests got caught up front. I set clear rules for who gets which level of access by role. I reported usage every quarter, and later moved the training online and tracked completion in Power BI.
What changed
Requests got about 50% faster. Quarterly reviews made removing old access a normal step. Audit prep went from about two weeks to under a day.

Query behind the quarterly view · BigQuery-style SQL over an access event log 
-- access_events: every grant and removal since the program started
-- requests: one row per access request
WITH changes AS (
  SELECT
    site,
    DATE_TRUNC(event_date, QUARTER)                AS quarter,   -- first day of the quarter
    COUNTIF(event_type = 'granted')                AS added,
    COUNTIF(event_type = 'removed')                AS removed
  FROM access_events
  GROUP BY site, quarter
),
turnaround AS (
  SELECT
    site,
    DATE_TRUNC(approved_date, QUARTER)             AS quarter,
    APPROX_QUANTILES(
      DATE_DIFF(approved_date, submitted_date, DAY), 2
    )[OFFSET(1)]                                   AS median_days
  FROM requests
  WHERE status = 'Approved'
  GROUP BY site, quarter
)
SELECT
  c.site, c.quarter, c.added, c.removed,
  SUM(c.added - c.removed) OVER (
    PARTITION BY c.site ORDER BY c.quarter
  )                                                AS active_users,  -- running total from day 1
  t.median_days
FROM changes AS c
LEFT JOIN turnaround AS t USING (site, quarter)
ORDER BY c.site, c.quarter;
